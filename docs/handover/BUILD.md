# Сборка: боевой путь и путь стенда

Обычно собирать ничего не нужно: готовый архив приходит вместе с выпуском ([RELEASE.md](RELEASE.md)). Эта страница — для проверки
и для случаев, когда выпуск нужно собрать самим из метки.

## Требования

- Node.js 22 (LTS) и npm 10+. Другого ПО не нужно.
- Доступ к npm-реестру при установке зависимостей.

## Команды

```bash
git clone https://github.com/Paulos99/MF_StP.git && cd MF_StP
git checkout v1.0.0            # нужная метка выпуска
npm ci                         # точная установка по package-lock.json (не npm install)
npm test                       # проверка раскладки панелей (ceiling layout)
npm run build:esbuild          # готовая папка сайта: dist/
```

Сборка `build:esbuild` — основная: ею собираются и стенд, и выпуск (`scripts/build-esbuild.mjs`; перед сборкой она очищает `dist/`).
Команда `npm run build` (Vite) даёт рабочую, но другую по составу сборку; для выпусков не используется.

## Путь на сайте (базовый путь)

Задавать путь **не нужно**: в сборке все адреса относительные (`./assets/app.js`, `./logo.png`), поэтому тот же архив открывается:

| Окружение | Адрес |
|---|---|
| Боевой | `https://stp-multiframe.ru/calc/` |
| Стенд GitHub Pages | `https://paulos99.github.io/MF_StP/` |
| Любой другой путь (например, тестовый поддомен) | положить содержимое `dist/` в этот каталог |

Условие: адрес в браузере должен заканчиваться на `/` (иначе относительные ссылки собьются). Сервер должен перенаправлять `/calc` → `/calc/`
(есть в [примере nginx](../../deploy/nginx/calc.conf)). Переменных окружения у сборки нет ([ENV.md](ENV.md)).

## Что получается в `dist/`

`index.html`, `logo.png`, `logo-multiframe.png`, `buy.png`, `add-image.png`, папка `assets/` (`app.js`, `app.css` и подгружаемые части:
PDF-экспорт, библиотеки `jspdf` и `html2canvas` — они **входят в сборку**, с чужих серверов не подгружаются). В готовом архиве выпуска добавлен файл
`version.txt` с номером выпуска (по нему скрипт установки проверяет, что включена нужная версия).

## Проверка собранного

```bash
test -f dist/index.html && grep -q 'src="./assets/app.js"' dist/index.html && echo "основной файл подключён"
grep -rqE 'import\(["'"'"'`]https?://' dist && echo "ЕСТЬ подгрузка скриптов с чужих серверов!" || echo "подгрузки скриптов с чужих серверов нет"
npx vite preview --outDir dist     # или любой статический сервер: python3 -m http.server -d dist
```

## Проверочный стенд на GitHub Pages

Рабочий процесс `.github/workflows/deploy.yml` («Deploy to GitHub Pages») при каждом изменении `main` собирает сайт и публикует его на
https://paulos99.github.io/MF_StP/ . Владелец видит результат до того, как поставит метку выпуска. Стенд не зависит от боевого сервера и не влияет на него. Стенд скрыт от поисковиков: при сборке рабочим процессом GitHub Pages в `index.html` добавляется `<meta name="robots" content="noindex,nofollow">` и создаётся `robots.txt` с `Disallow: /` (`scripts/build-esbuild.mjs`); в выпуске по метке и в локальной сборке их нет, на стенде нет и Метрики.
